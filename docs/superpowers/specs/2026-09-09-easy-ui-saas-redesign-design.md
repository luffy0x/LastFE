# Easy UI SaaS 全站重设计方案

日期：2026-09-09  
状态：已实现（2026-09-09）  
参考：[DarkInventor/easy-ui](https://github.com/DarkInventor/easy-ui) 的 Ez SaaS 模板（MIT）

## 1. 背景与目标

Knowledge Frontier 当前使用全屏战略地图组织求职知识。此次改造采用 easy-ui 的 Ez SaaS 作为完整页面骨架，将产品调整为以搜索和内容浏览为首要任务的知识平台。

目标：

- 首屏直接提供搜索，不经过营销介绍或地图交互才能访问内容。
- 保留“面经记录、学习资料、八股盛宴、项目推荐、算法手撕”五类内容。
- 全站页面统一为 Ez SaaS 风格，并支持浅色、深色双主题。
- 保留现有 URL、数据访问、投稿审核和 API 行为。
- 保留 Next.js 16、React 19、Tailwind CSS 4，不降级到 easy-ui 示例工程的旧版本。

非目标：

- 不增加登录、收藏、学习进度或 AI 问答功能。
- 不修改 Supabase 数据结构、GitHub 审核流程或部署方式。
- 不将 easy-ui 仓库整体复制进项目，也不引入其全部依赖。
- 不保留战略地图页面或单独的地图入口。

## 2. 已选方案

采用“适配式重构”：保留现有业务层和路由，只迁移 Ez SaaS 的页面结构、视觉语言与必要组件。

未采用的方案：

- 整仓移植：虽然最接近模板原始代码，但 easy-ui 当前基于 Next.js 14、React 18 和 Tailwind CSS 3，与本项目的 Next.js 16、React 19 和 Tailwind CSS 4 存在明显兼容成本。
- 分阶段替换：风险较低，但会让线上页面在较长时间内保持两套视觉体系，不符合本次“整体重做”的目标。

## 3. 页面架构

### 3.1 全站壳层

根布局提供统一的 `SiteHeader`、主内容区域和 `SiteFooter`。

顶部导航包含：

- 产品标识与首页入口；
- 五类内容入口；
- 全局搜索入口；
- 浅色/深色主题切换；
- 投稿主按钮。

移动端将分类导航收进可访问的菜单，搜索和投稿仍保持直接可达。

### 3.2 首页 `/`

首页按以下顺序组织：

1. 搜索主视觉：产品定位、全局搜索框、投稿次要入口。
2. 内容统计：公开内容总量、近七日新增。
3. 五类内容入口：面经、学习资料、八股、项目、算法。
4. 最新内容：跨分类展示最近发布的内容摘要。
5. 投稿引导：说明审核机制与隐私边界。
6. 页脚：站点说明与必要链接。

原战略地图、镜头控制、移动标记和地图交互全部退出产品。

### 3.3 分类页 `/regions/[slug]`

继续沿用现有路径，页面统一为：

- 面包屑和分类介绍；
- 当前分类适用的搜索、标签与字段筛选；
- 内容卡片或紧凑列表；
- 空状态、清除筛选入口和分页；
- 当前分类的投稿入口。

五类页面共享一个分类页组件，通过配置驱动差异，避免复制页面结构。

### 3.4 内容详情页 `/content/[id]`

采用阅读优先的单栏正文布局：

- 面包屑、标题、作者、发布时间、分类和标签；
- 最大阅读宽度受控的 Markdown 正文；
- 外部资源链接使用明确标识；
- 返回分类和投稿入口；
- 不使用营销卡片打断长文阅读。

### 3.5 投稿流程

`/submit`、`/submit/[slug]` 和 `/submitted` 使用相同壳层与表单组件：

- 投稿目录继续展示五类内容；
- 分类表单字段和校验规则保持不变；
- 保留“提交后进入审核，不会直接公开”的说明；
- 成功页给出返回首页和继续浏览的明确路径。

## 4. 模块边界

### 4.1 内容分类配置

现有 `features/map/regions.ts` 同时包含业务分类字段和地图几何数据。改造时将业务数据拆到内容领域，例如 `features/content/categories.ts`，只保留：

- slug、名称、描述和主题标识；
- 投稿字段；
- 筛选字段；
- 摘要字段。

地图路径、锚点、镜头参数和连线配置不进入新结构。

### 4.2 共享页面组件

新增或整理以下职责单一的组件：

- `SiteHeader`：桌面和移动导航、搜索入口、投稿入口、主题切换。
- `SiteFooter`：站点信息和辅助链接。
- `ThemeProvider` / `ThemeToggle`：主题初始化、系统偏好和用户选择。
- `SearchHero`：首页搜索主区域。
- `CategoryGrid` / `CategoryCard`：五类内容入口。
- `LatestContent` / `ContentCard`：最新内容和分类内容摘要。
- 基础 UI：`Button`、`Badge`、`Card`、`Input` 和必要的空状态。

业务状态、异步请求和事件编排继续放在现有或新增的自定义 Hook 中；展示组件只负责组合和渲染。

### 4.3 移除范围

完成替代功能并通过测试后，移除：

- 战略地图组件；
- 地图镜头与探索者移动 Hook；
- SVG 地图几何和地图专属样式；
- 只验证地图交互的单元测试与 E2E 用例。

对应的分类导航、键盘可达性和响应式行为必须先由新测试覆盖，避免功能缺口。

## 5. 视觉与主题

### 5.1 视觉方向

沿用 Ez SaaS 的稳定产品感：清晰顶栏、宽松首屏、明确行动按钮、统一卡片和分区节奏。页面不再使用战术地图、扫描线、坐标、操作员或领地语言。

中文产品文案保持直接：统一使用“分类”“内容”“投稿”“搜索”等词，不再使用“情报”“领地”“任务”等隐喻。

### 5.2 双主题

- 浅色主题：白色与浅灰背景、深色正文、靛蓝主色。
- 深色主题：深灰蓝背景、浅色正文、提高边界和正文对比度。
- 默认跟随系统；用户手动选择后持久保存。
- 服务端输出和客户端主题初始化不得产生明显闪烁或 hydration 警告。
- 两套主题均使用语义令牌，不在业务组件内散落硬编码颜色。

### 5.3 响应式与可访问性

- 重点验证 375、768、1024 和 1440 像素宽度。
- 所有交互目标至少 44×44 像素。
- 保留跳转主要内容链接、语义化区域、可见焦点和完整键盘路径。
- 移动导航打开后应正确管理焦点，并允许 Escape 关闭。
- 尊重 `prefers-reduced-motion`，不增加持续或干扰阅读的动画。

## 6. 依赖策略

计划只增加：

- `next-themes`：处理系统主题、用户选择、持久化和首屏主题初始化。
- `lucide-react`：提供一致、可访问的界面图标。

不引入 easy-ui 的完整依赖集合，也不引入 Contentlayer、MDX、Framer Motion、完整 Radix 套件或旧版 Tailwind 配置。若实现中发现原生元素无法可靠满足移动菜单或对话框的焦点管理，再单独评估最小 Radix 依赖。

## 7. 数据流与错误处理

- 首页服务端调用内容仓库的 `stats()` 和 `list()`，分别获取统计与最新内容。
- 分类页服务端解析查询参数，并通过 `list()` 完成搜索、字段筛选、标签筛选和分页。
- 全局搜索继续调用 `/api/search`，并统一经过 `@/utils/request`。
- 详情页继续通过 `get(id)` 获取内容；不存在或已撤回内容返回 404。
- 投稿继续使用现有 `/api/submissions` 流程，不改变校验、限流和审核语义。

错误状态包括：

- 首页或分类列表加载失败时提供可重试提示；
- 搜索失败保留查询文本并允许重试；
- 无内容与无筛选结果使用不同提示；
- 投稿校验错误显示在对应字段附近；
- 投稿网络或服务错误保留用户输入，并提供再次提交入口。

## 8. 测试与验收

### 8.1 自动化验证

- 组件测试：主题切换、移动导航、首页五类入口、内容卡片和空状态。
- 页面测试：首页数据渲染、分类筛选与分页、详情 404、投稿目录和成功页。
- 业务回归：搜索 API、投稿 API、内容仓库和 Supabase 测试保持通过。
- E2E：从首页搜索或分类进入内容详情，并完成投稿主路径。
- 布局 E2E：375、768、1024 和 1440 像素下无横向滚动，导航和内容不遮挡。

### 8.2 验收标准

- 用户进入首页即可搜索或进入任一分类。
- 五类内容、现有深链接、筛选参数和投稿流程保持有效。
- 浅色、深色及系统主题切换正确，刷新后保留用户选择。
- 战略地图及相关视觉语言不再出现在用户页面。
- 未降低 Next.js、React 或 Tailwind CSS 版本。
- lint、类型检查、单元测试、构建和相关 E2E 全部通过。

## 9. 风险与控制

- **视觉改造范围大**：先建立共享壳层和主题令牌，再逐页迁移，避免页面各自实现。
- **Tailwind 版本差异**：将 easy-ui 仅作为视觉和结构参考，按 Tailwind CSS 4 语法重新实现。
- **主题闪烁**：在根布局中采用 SSR 安全的主题初始化，并加入针对性的渲染测试。
- **地图删除造成回归**：先迁移分类配置和入口，再删除地图代码；以路由和 E2E 覆盖替代地图测试。
- **依赖膨胀**：初始仅允许 `next-themes` 与 `lucide-react`，其他依赖必须有明确不可替代理由。
