# 求职知识战略地图设计规格

## 1. 文档状态

- 日期：2026-09-01
- 状态：用户已确认，进入实施计划阶段
- 项目阶段：新项目 MVP
- 工作名称：Knowledge Frontier（暂定）

## 2. 背景与目标

本项目面向学生与求职者，提供公开可访问的面经、学习资料、八股知识、项目经验和算法内容。网站不是传统栏目首页，而是一张全屏科幻战略地图：不同内容类型是地图上的领地，访客通过点击领地、观看探索者角色移动并抵达目标后进入对应内容页。

任何访客都可以浏览和搜索内容，也可以在无需注册的情况下投稿。投稿不会立即公开，而是进入 GitHub Issues 审核流程；维护者批准后，内容才会出现在网站上。

MVP 的目标是建立以下最短闭环：

1. 访客在可拖拽、缩放的战略地图上探索内容领地。
2. 访客按领地、关键词和标签查找内容。
3. 访客通过领地专属表单匿名提交内容。
4. 维护者在 GitHub Issues 中审核，不使用自建管理后台。
5. 审核通过的内容在一分钟内公开，后续可以撤下。

## 3. 范围

### 3.1 MVP 包含

- 全屏科幻战略地图首页。
- 可拖拽、缩放的 SVG 地图，以及可移动的探索者角色。
- 面经、学习资料、八股、项目和算法五个初始领地。
- 数据驱动的领地配置，支持后续增加板块。
- 每个领地的内容面板、筛选、搜索和详情页。
- 五类内容的领地专属投稿表单。
- 可选投稿昵称。
- Markdown 内容正文。
- GitHub Issues 审核流程。
- SQLite 持久化已发布内容。
- 匿名投稿防刷、输入校验和 Markdown 安全渲染。
- 单机 Docker 部署、日志、健康检查和每日备份。

### 3.2 MVP 不包含

- 用户注册、登录、个人主页或用户关系。
- 自建管理后台。
- 评论、点赞、收藏或站内通知。
- 文件上传、文件托管或下载内容安全扫描。
- 多管理员权限系统。
- 内容推荐算法。
- 个性化探索进度、角色养成或角色外观定制。
- 移动端原生应用。
- WebGL/Three.js 三维地形。
- 可视化地图编辑器；新增领地通过修改配置和 SVG 后重新发布。

## 4. 已确认的产品决策

- 所有已发布内容对所有访客公开。
- 投稿无需注册。
- 投稿必须经过维护者审批。
- GitHub Issues 是唯一审核界面。
- 初始领地为面经、学习资料、八股、项目和算法，后续可以增加。
- 所有领地都允许匿名投稿，并使用同一套 GitHub Issue 审核流程。
- 面经包含公司/部门、岗位、标签、可选昵称和 Markdown 正文。
- 轮次等信息通过标签表达，不单独增加字段。
- 学习资料是外部下载链接或跳转链接，不在本站存储文件。
- 首页采用全屏科幻指挥地图，不使用普通卡片式频道首页。
- 地图使用连续领土结构、深色全息 HUD、网格、扫描和低饱和区域色。
- 地图使用 SVG、CSS 和 Web Animations API，不引入 Canvas 或 Three.js。
- 访客点击领地后，探索者角色沿路线移动，抵达后自动进入对应页面。
- 进入领地后保留地图背景，内容通过情报面板呈现。
- 新增领地通过配置、SVG 边界和字段定义完成，并重新发布网站。
- 主要技术栈为 React、TypeScript、Next.js 和 SQLite。
- 首版部署在现有加州服务器上，并尽量减少中国大陆访客的跨境动态请求。

## 5. 信息架构与页面

### 5.1 路由

| 路由 | 用途 |
| --- | --- |
| `/` | 全屏战略地图与全局搜索入口 |
| `/regions/[slug]` | 对应领地的地图背景、情报面板、搜索与筛选 |
| `/content/[id]` | 内容详情档案；保留返回所属领地的入口 |
| `/submit` | 选择投稿领地 |
| `/submit/[slug]` | 根据领地配置渲染专属投稿表单 |
| `/submitted` | 投稿成功提示，不公开私有 Issue 地址 |

网站不提供 `/admin` 或其他审核页面。

### 5.2 首页

首页首屏就是科幻指挥地图，不再额外放置传统 Hero、功能卡片或信息流。地图采用连续领土结构，初始包含面经、学习资料、八股、项目和算法五个领地。

固定 HUD 仅保留：

- 产品标识。
- 全局搜索入口。
- 内容总量和最近新增等少量状态。
- 地图缩放、复位和领地列表入口。
- 当前选中领地的名称与摘要。

地图默认展示全局视角。地图资产本身不嵌入未审核内容，只展示已发布内容数量等缓存统计。

### 5.3 地图与探索者交互

- 鼠标拖拽地图、滚轮缩放，触控设备支持单指拖拽和双指缩放。
- 领地在悬停、键盘聚焦和选中时显示不同的边境高亮。
- 点击领地后立即预取目标路由，并锁定本次目的地。
- 探索者角色沿配置路线移动，正常距离的动画控制在 0.6–1 秒。
- 角色抵达后自动进入 `/regions/[slug]`。
- 动画过程中再次选择领地时，取消当前动画并从角色当前位置转向新目标；页面状态不依赖 `animationend` 才成立。
- 开启 `prefers-reduced-motion` 时跳过非必要移动，直接定位并进入目标领地。
- 浏览器返回地图时恢复上一次镜头和角色位置；直接访问领地深链接时，将角色定位到该领地落点。

### 5.4 领地内容页

领地页继续保留已抵达区域的地图背景，并以右侧“情报面板”承载内容。桌面端地图仍占据可见区域，面板宽度不超过主视口约三分之二；移动端面板变为全屏底部抽屉。

情报面板包含：

- 领地名称和描述。
- 当前领地内搜索。
- 领地专属筛选项和标签。
- 按发布时间倒序的内容列表。
- 投稿入口。
- 返回战略地图入口。

内容详情使用独立 URL，并以“档案”视觉呈现。正文区域优先保证阅读宽度、字号、对比度和代码块可用性，不为了游戏效果牺牲长文阅读。

### 5.5 初始领地

| 领地 | 主要展示与筛选字段 |
| --- | --- |
| 面经 | 公司/部门、岗位、标签、正文 |
| 学习资料 | 标题、简介、标签、外部链接 |
| 八股 | 标题、知识分类、标签、Markdown 正文 |
| 项目 | 标题、技术栈、仓库或演示链接、Markdown 正文 |
| 算法 | 标题、来源、难度、题目链接、Markdown 题解 |

学习资料、项目和算法中的外部链接必须明确标记，在新标签页打开。本站不代理、不缓存、不扫描外部文件。

### 5.6 移动端与无障碍入口

- 地图控件的最小可点击尺寸为 44×44 CSS 像素。
- 提供与地图内容等价的“领地列表”，地图不是唯一导航方式。
- 每块 SVG 领地具有按钮语义、可见焦点和可读名称，可用 Tab 与 Enter 操作。
- 领地含义不只依赖颜色，同时使用边界、名称和选中状态。
- 固定 HUD 不得遮挡键盘焦点或主要内容。
- 用户可以复位镜头，避免在缩放或拖拽后迷失位置。

## 6. 投稿数据模型

### 6.1 领地配置

领地由版本控制中的 TypeScript 配置和 SVG 资产定义。每个领地至少包含：

- 唯一 `slug`、展示名称和简短描述。
- SVG 边界路径。
- 探索者落点。
- 镜头中心和缩放级别。
- 与其他领地相连的路线及路径点。
- 领地主题色；颜色只用于辅助识别。
- 投稿字段定义、筛选字段和内容展示配置。
- 目标页面路由和启用状态。

构建时必须校验领地 `slug` 唯一、落点有效、启用领地均有路由，并确保路线图连通。新增领地需要修改配置、绘制 SVG 边界和补充字段校验，然后重新构建发布；MVP 不支持运行时可视化编辑。

### 6.2 公共投稿字段

所有领地共享标题、标签、可选昵称和可选 Markdown 正文。服务端先应用公共约束，再按领地配置应用专属约束。未填写昵称时公开显示“匿名”。

### 6.3 面经投稿

| 字段 | 要求 |
| --- | --- |
| 公司/部门 | 必填，1–80 个字符 |
| 岗位 | 必填，1–80 个字符 |
| 标签 | 必填，1–5 个；每个 1–24 个字符 |
| 昵称 | 可选，最多 40 个字符 |
| Markdown 正文 | 必填，最多 50 KiB |

展示标题由系统生成：`公司/部门 · 岗位`。轮次、面试阶段、技术方向等通过标签表达。

### 6.4 学习资料投稿

| 字段 | 要求 |
| --- | --- |
| 标题 | 必填，1–120 个字符 |
| 链接 | 必填，最长 2048 个字符，仅允许 `http` 或 `https` |
| 简介 | 可选，最多 2000 个字符 |
| 标签 | 必填，1–5 个；每个 1–24 个字符 |
| 昵称 | 可选，最多 40 个字符 |

### 6.5 八股、项目与算法投稿

| 领地 | 专属字段 |
| --- | --- |
| 八股 | 知识分类、Markdown 正文 |
| 项目 | 技术栈、可选仓库链接、可选演示链接、Markdown 正文 |
| 算法 | 来源、难度、可选题目链接、Markdown 题解 |

所有外部链接最长 2048 个字符，只允许 `http` 或 `https`。具体字符长度、枚举值和必填规则在领地配置中声明，并由客户端与服务端共享同一校验定义。

### 6.6 已发布内容

SQLite 中使用统一内容表保存公共字段，并通过 `region_slug` 关联领地。每条记录至少包含：

- 稳定公开 ID。
- 领地 `slug`。
- GitHub Issue 编号，且唯一。
- 发布状态：`published` 或 `withdrawn`。
- 标题、可选简介、可选昵称和可选 Markdown 正文。
- 可选外部链接。
- 经领地校验器验证的专属元数据。
- 创建、发布和最后更新时间。

专属元数据以 JSON 保存，但写入前必须通过对应领地的服务端校验器；常用筛选字段通过 SQLite JSON 表达式查询。标签采用独立标签表和内容标签关联表，避免同义大小写造成重复。搜索在 MVP 阶段使用 SQLite 参数化查询和分页；数据规模增长并出现实测瓶颈后，再评估 FTS5 或 PostgreSQL。

## 7. 系统架构

### 7.1 组件

1. **Next.js Web 应用**
   - 使用 React 和 TypeScript。
   - 提供公开页面、投稿 API 和 GitHub webhook 入口。
   - 所有浏览器端 API 请求统一通过 `@/utils/request`，页面组件不直接调用 `fetch`。
   - 公开页面采用服务端渲染和可失效缓存。

2. **地图引擎**
   - 使用语义化 SVG 渲染领地、边界、路线、标记和探索者角色。
   - 使用 CSS 与 Web Animations API 完成高亮、路径移动、镜头过渡和页面淡入。
   - 地图状态与内容数据分离；地图只依赖领地配置和公开统计。
   - 交互逻辑集中在独立 hook 和控制器中，视图组件只负责组合与渲染。

3. **统一内容引擎**
   - 使用公共内容模型、标签、搜索、审核和详情渲染逻辑。
   - 通过领地配置加载专属字段校验、筛选器和显示组件。
   - 新领地不得复制整套列表、投稿和审核流程。

4. **SQLite**
   - 保存已发布和已撤下的内容，不承担审核队列职责。
   - 数据文件位于容器外的持久化目录。
   - 单一应用实例负责写入，避免多写者协调问题。

5. **私有 GitHub 仓库**
   - 保存待审核 Issue，避免未批准内容提前公开。
   - 使用细粒度访问令牌，仅授予该仓库所需的 Issues 读写权限。
   - 令牌与 webhook secret 只存在于服务器环境变量或部署密钥中，不进入仓库、日志或客户端。

6. **Nginx**
   - 终止 HTTPS、反向代理、压缩静态资源并提供基础限流。
   - 静态资源使用长缓存；HTML 缓存可被发布流程主动失效。

7. **定时校准任务**
   - 每 10 分钟读取最近变更的审核 Issue，与 SQLite 状态对账。
   - 用于补偿 webhook 丢失或应用短暂不可用。

### 7.2 部署边界

MVP 使用一台 Linux/amd64 加州服务器和 Docker Compose。应用、Nginx 与持久化目录位于同一台服务器。系统不依赖中国大陆服务器或大陆 CDN，因此无法承诺固定的跨境时延；页面尽量静态化、压缩并减少请求数量。

正式公开访问前需要一个解析到服务器的域名和有效 TLS 证书。域名购买与备案不属于本项目实现范围；没有备案时不使用要求备案的中国大陆 CDN 节点。

### 7.3 视觉语言

- 基础背景使用深海军蓝至近黑色，网格与扫描线保持低对比度。
- 领地使用低饱和政治区块色，青色辉光用于边界和交互反馈，暖金色只用于当前目标和关键状态。
- 不使用卡通岛屿、儿童插画、Emoji 图标或高饱和糖果色。
- HUD 采用清晰几何边框、轻量玻璃层和有限阴影，不堆叠无意义装饰。
- 字体优先使用系统字体栈：`system-ui`、`PingFang SC`、`Microsoft YaHei`、`sans-serif`，避免依赖中国大陆访问不稳定的远程字体服务。
- 正文对比度至少达到 WCAG AA；正文最小字号 16px、行高至少 1.5。
- 动效只用于表达选择、移动、抵达和层级切换；不使用持续高成本的全屏粒子或 WebGL 特效。

### 7.4 运行时数据流

1. 服务端渲染首页时输出领地配置和已发布内容统计，不输出待审核数据。
2. 客户端地图引擎管理镜头、当前角色位置和选中领地。
3. 访客选择领地后，应用预取 `/regions/[slug]`，同时启动角色移动。
4. 角色抵达且目标路由可用时，客户端导航至领地页面；目标改变时取消旧导航。
5. 领地页面由服务端查询 SQLite，返回该领地的已发布内容、筛选项和分页信息。
6. 投稿通过服务端创建 GitHub Issue；审核 webhook 更新 SQLite 并失效对应缓存。

## 8. 投稿与审核流程

### 8.1 投稿

1. 访客从领地页进入对应投稿表单，或先在 `/submit` 选择领地。
2. 客户端执行基础提示，服务端执行完整校验。
3. 服务端校验自托管 ALTCHA 答案、请求频率和重复内容指纹。
4. 服务端调用 GitHub API，在私有仓库创建 Issue。
5. Issue 初始标签为 `submission`、`pending`，以及 `region:<slug>`。
6. 创建成功后跳转至 `/submitted`；不向访客暴露私有 Issue URL。

Issue 标题由系统生成。Issue 正文包含服务端生成的固定元数据区块和投稿正文；解析器只接受该固定格式，并在发布前再次校验全部字段。

### 8.2 审核状态

- **批准**：维护者添加 `approved` 标签。webhook 将内容按 Issue 编号幂等写入 SQLite，移除 `pending`，添加 `published`，刷新相关页面缓存，然后关闭 Issue。
- **拒绝**：维护者在没有 `approved` 标签时直接关闭 Issue。内容不写入公开数据。
- **撤稿**：维护者向已批准 Issue 添加 `unpublish` 标签。对应记录改为 `withdrawn`，并立即从列表、搜索和详情页隐藏。
- **重新发布**：维护者移除 `unpublish`，再将 `approved` 标签移除并重新添加。系统重新校验 Issue 当前内容后更新并发布。

数据库写入和标签回写失败时不得静默忽略。事件以 GitHub Issue 编号和 webhook delivery ID 做幂等控制；失败事件记录不含令牌和投稿者 IP，并交由定时校准任务重试。

## 9. 搜索与筛选

- 面经搜索范围：公司/部门、岗位、标签和正文。
- 学习资料搜索范围：标题、简介和标签。
- 八股搜索范围：标题、知识分类、标签和正文。
- 项目搜索范围：标题、技术栈、标签和正文。
- 算法搜索范围：标题、来源、难度、标签和正文。
- HUD 提供全局搜索入口，结果按领地分组；领地面板默认只搜索当前区域。
- 搜索结果按发布时间倒序排列，并使用固定页大小分页。
- 标签匹配使用规范化值，展示时保留面向用户的标签文本。
- 空查询返回最新内容；无结果时提供清晰空状态和清除筛选入口。

## 10. 安全与隐私

### 10.1 匿名投稿防护

- 使用自托管 ALTCHA，避免依赖 Google 验证服务。
- Nginx 与应用层共同限流；默认每个来源 IP 每小时最多成功提交 10 次。
- 使用隐藏字段识别基础机器人。
- 24 小时内拒绝相同内容指纹的重复投稿。
- 频率阈值作为配置项，出现校园 NAT 误伤时可以调整。

### 10.2 内容安全

- Markdown 不允许原始 HTML。
- 渲染器只输出允许的 Markdown 节点。
- 链接仅允许安全协议；所有用户提交的站外链接带 `rel="nofollow noopener noreferrer"`。
- 所有数据库查询使用参数化语句。
- webhook 必须验证 GitHub HMAC 签名，并限制请求体大小。
- 投稿接口不使用身份 Cookie，避免引入无意义的登录和 CSRF 状态。

### 10.3 隐私

- 不要求投稿者提供邮箱、手机号或真实姓名。
- 昵称完全可选。
- IP 仅用于短期限流和安全日志，不写入内容记录。
- 日志不记录令牌、完整 webhook secret、完整投稿正文或其他敏感值。

## 11. 错误处理

- 目标领地配置无效：构建失败，不发布带断裂路线或缺失页面的地图。
- 角色移动中重复选择：取消当前动画，从当前位置重新规划目标；不得触发旧目标跳转。
- 目标页面预取失败：角色停止在目标领地并显示重试提示，不跳转到错误页。
- 地图脚本加载失败：显示等价领地列表，保证核心导航仍可使用。
- 字段错误：在对应字段旁显示明确、可修正的提示。
- ALTCHA 失败：保留表单内容，允许重新验证。
- GitHub API 暂时不可用：返回可重试错误，保留当前页面中的表单内容，不显示成功状态。
- webhook 重复：返回成功但不重复创建内容。
- webhook 处理失败：记录安全的错误上下文并允许 GitHub 重试；定时任务最终校准。
- 外部资料链接失效：MVP 不自动探测，在内容页提供明确的站外链接提示；后续可增加举报或巡检。
- SQLite 不可写：拒绝发布同步并触发健康检查失败，不返回虚假的发布成功。

## 12. 缓存与中国大陆访问策略

- 地图 SVG、纹理和领地配置属于版本化静态资产，使用长缓存。
- 首页、领地页和详情页输出可缓存 HTML。
- 发布、更新或撤稿时，只失效受影响的领地、详情页、全局搜索和首页统计。
- 首屏地图不加载完整内容数据，只加载领地配置和小型统计快照。
- JavaScript 包保持精简；不在 MVP 引入 Canvas、WebGL 或 Three.js。搜索和筛选优先通过服务端生成结果，避免首次加载完整数据集。
- Nginx 开启压缩和静态资源长缓存。
- 部署后使用中国大陆不同地区的外部探测验证 DNS、TLS、首字节和页面可用性。
- 如果实测跨境访问不稳定，后续优先评估香港节点或无需大陆备案的邻近区域部署；不在 MVP 中承诺通过第三方 CDN 解决全部跨境网络问题。

### 13.2 集成测试

- 验证 webhook 正确签名、错误签名、重复 delivery 和乱序事件。
- 验证缓存失效只影响相关页面。

### 13.3 端到端测试

- 使用鼠标、触控模拟和键盘选择领地。
- 验证探索者移动后自动进入正确的领地 URL。

- 开启减少动态效果后直接进入领地。
- 使用领地列表备用入口完成导航。
- 浏览五个领地并使用搜索和标签筛选。
- 完成五类内容投稿。

- 模拟拒绝和撤稿。

### 13.4 构建检查

每次交付至少运行 lint、TypeScript 类型检查、自动化测试和生产构建。地图首页增加 375px、768px、1024px 和 1440px 视觉回归检查，并验证地图资产体积和首屏布局偏移。具体命令在项目脚手架确定后写入仓库说明和 CI。

## 14. 验收标准

1. 首页以全屏科幻战略地图呈现五个初始领地，不出现传统频道卡片首屏。
2. 地图支持拖拽、缩放、复位、鼠标选择和键盘选择。
3. 点击领地后探索者沿路线移动，并在正常网络下 0.6–1 秒左右抵达后自动进入正确 URL。
4. 动画期间更换目标不会进入旧领地；减少动态效果模式会跳过非必要动画。
5. 新增测试领地只需要配置、SVG 边界、字段定义和一次重新发布，不复制通用页面与审核代码。
6. 无需登录即可浏览、搜索和筛选全部已发布内容。
7. 无需登录即可向五个领地投稿，并在成功后生成私有待审核 Issue。
8. 未批准内容不会出现在公开页面、搜索结果或静态输出中。
9. GitHub webhook 正常送达时，添加 `approved` 标签后一分钟内公开内容；webhook 丢失时，由 10 分钟一次的校准任务恢复。
10. 直接关闭未批准 Issue 不会发布内容。
11. GitHub webhook 正常送达时，添加 `unpublish` 后一分钟内从公开页面撤下内容；webhook 丢失时，由校准任务恢复。
12. 重复 webhook 不会产生重复记录。
13. Markdown 中的原始 HTML 和危险链接不会执行。
14. 外部链接均有站外提示和安全链接属性。
15. 每日 SQLite 备份可在空数据库环境中完成恢复演练。

## 15. 运维与恢复

- 提供 `/api/health`，检查应用进程和 SQLite 可读写状态，但不泄露配置详情。
- 每日使用 SQLite 一致性备份机制创建备份，保留最近 14 天。
- 至少在首次上线前完成一次从备份恢复到临时目录的演练。
- GitHub token、webhook secret 和 ALTCHA 密钥通过服务器密钥配置注入。
- 镜像默认构建为 `linux/amd64`。
- 日志结构化记录请求 ID、事件类型和错误类别，不记录密钥或完整投稿内容。

## 16. 后续演进条件

以下能力不提前加入，只在出现明确需求或瓶颈后评估：

- 内容量或并发写入超过单机 SQLite 的实际承载后，迁移 PostgreSQL。
- 普通查询出现可测量性能问题后，引入 SQLite FTS5 或独立搜索服务。
- 审核者增加且 GitHub 标签不足以表达权限后，增加管理后台。
- 垃圾投稿绕过当前防护后，提高 ALTCHA 难度、调整限流或增加封禁规则。
- 中国大陆跨境访问监测持续不达标后，迁移至香港或其他邻近节点。
